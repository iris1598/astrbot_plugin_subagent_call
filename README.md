# astrbot_plugin_subagent_call

角色扮演场景下的「子代理呼叫」插件。

主对话模型**不使用工具**（人格的 tools 设为 `[]`），改为在需要外部能力时输出一个简易标签，
例如 `[呼叫Iris:查今天的天气]`。插件负责把标签清洗掉、启动一个拥有完整工具与 Skill 的隔离
子代理去干活，再把结果回传主模型生成终稿。

目前只支持**一个**子代理，不需要在标签里指定是谁——冒号前的内容只是写给人看的标签，
解析时会被忽略，所以 `[呼叫:查天气]` 或 `[呼叫随便什么名字:查天气]` 一样能触发。

## 工作流程

以主模型输出 `（歪头）让你久等了。[呼叫Iris:查今天北京的天气]` 为例：

1. 用户看到 **（歪头）让你久等了。**（标签已清除）
2. 用户看到 **🔔 正在呼叫 Iris…**（文案可配置）
3. 子代理跑工具循环完成任务
4. 主模型基于结果生成终稿并作为最终回复发出

标签会**保留在上下文历史**中，所以下一轮模型知道自己呼叫过子代理、拿到了什么：

```
… user → assistant(含标签) → user(子代理结果) → assistant(终稿)
```

## 安装与配置

1. 把本目录放到 `AstrBot/data/plugins/` 下，在 WebUI 插件页重载。
2. 在插件配置里给这一个子代理选好：
   - **人格**（`subagent_persona_id`）——说话风格、语气、要不要吐槽，都写在人格里；
   - **模型**（`subagent_provider_id`，建议选工具调用能力强的）。
   子代理名字（`subagent_name`，默认 `Iris`）只影响规则里的示例标签和启动提示，可留默认。
3. 建议把主对话人格的 **tools 设为 `[]`**，并**关闭全局流式输出**。

## 前置条件

| 条件 | 说明 |
|---|---|
| 主对话人格 tools = `[]` | 否则模型可能直接调用工具，而不是输出标签 |
| 关闭流式输出 | 流式模式下标签会在插件清洗之前就推送出去；插件启动时会打 WARNING 日志 |
| AstrBot >= 4.23.1 | 依赖 `on_agent_done` 钩子 |

## 主要配置项

标签格式固定为 `[呼叫任意标签:原因理由]`（中英文冒号均可），**不需要配置**；
冒号前的标签内容不参与匹配。

| 配置 | 默认 | 说明 |
|---|---|---|
| `tag_rules` | 内置规则全文 | 注入系统提示词的呼叫规则，默认值就是插件内置的那套，可直接在上面改 |
| `subagent_name` | `Iris` | 只用于渲染示例标签与启动提示，不影响标签识别 |
| `subagent_persona_id` | 空 | 子代理使用的人格（WebUI 下拉选择） |
| `subagent_provider_id` | 空 | 子代理使用的模型（WebUI 下拉选择），留空用会话默认模型 |
| `subagent_max_steps` | 15 | 子代理最大工具调用步数 |
| `context_window` | 6 | 注入子代理的主对话最近消息条数 |
| `enable_history_tool` | 开 | 给子代理一个按需查询主对话历史的工具 |
| `strip_media` | 开 | 转发上下文时把图片/语音替换为 `[图片]`/`[语音]` 占位符 |
| `send_first_text` | 开 | 是否发送清洗标签后的第一段正文 |
| `start_notice` | `🔔 正在呼叫 {name}…` | 启动提示文案 |
| `subagent_task_template` | 内置模板全文 | 交给子代理的任务模板 |
| `result_block_template` | 内置模板全文 | 回传给主模型的结果块模板 |
| `error_notice` | `⚠️ 子代理执行失败，请稍后再试。` | 呼叫失败时替代原回复发出；清空则不发送 |
| `max_rounds` | 1 | 终稿中再次出现标签时是否继续呼叫 |

三个模板类配置（`tag_rules` / `subagent_task_template` / `result_block_template`）的默认值
**就是插件内置的那套文本**，放在配置里是为了让你能直接看到、在此基础上改，而不是只能从代码里翻。

可用占位符：

| 配置 | 占位符 |
|---|---|
| `tag_rules` | `{example}`（示例标签）、`{name}` |
| `subagent_task_template` | `{reason}` |
| `result_block_template` | `{reason}`、`{result}` |
| `start_notice` | `{name}` |

写错的占位符会原样保留（不会抛错），所以不用担心多写花括号。

## 关于 `strip_media`（重要）

请保持开启。踩坑原因：

- AstrBot 只在 provider **显式声明了 `modalities`** 时，才会用 `[Image]` 占位符替换掉
  模型不支持的图片/语音（`astrbot/core/provider/modalities.py`）。没声明就默认「什么都支持」，
  原样透传。
- 主对话可能走的是**图片描述模型**（`astr_main_agent` 的 img_cap 分支）：图片被转成文字喂给主模型，
  但**原始 `image_url` 仍然留在会话历史里**。社交媒体图片链接很容易过期。
- 插件转发历史给子代理时若带上这个失效链接，就会得到
  `400 invalid_image: Downloaded response does not contain a valid JPG, PNG, WebP, or ICO image.`

因此插件默认把转发上下文里的多媒体块替换成文字占位符。这既避免了子代理请求被拒，
也保留了「这里本来有张图」的信息。

> 如果你确实想让子代理看图，除了关闭 `strip_media`，还应该给该 provider 配置好 `modalities`
> （或在 AstrBot 里配置「图片描述模型」），否则上游链接失效时仍会报错。

## 与其它「标签类」插件的共存（如 astrbot_plugin_favorability）

结论：**不冲突**。这类插件（好感度 `[FAV:±N]` / `[REL:up]` / `[STK:分类]` / `[MUTE:N]`）通常挂在
`on_llm_request` + `on_llm_response` 上，而本插件挂在 `on_agent_done`，AstrBot 的触发顺序是：

```
on_llm_request（双方各自注入：对方→system_prompt / extra_user_content_parts，本插件→system_prompt）
        ↓
Agent 运行，assistant 原文（含双方标签）写入 run_context.messages
        ↓
on_llm_response（对方）── 只清自己那几个标签，本插件的 [呼叫…] 不在它的正则里，原样留着
        ↓
on_agent_done（本插件）── 此时读到的 text 已被对方清干净，再清掉 [呼叫…] 并跑三段式
```

因为对方是**逐标签精确匹配**（正则里必须紧跟 `FAV`/`EVAL`/`REL`/`STK`/`MUTE` 关键词），
不会误删本插件的标签；而本插件也不会去动对方的标签。

两个已处理的交互点：

1. **终稿会分发一次 `on_llm_response`。** 终稿是本插件自己发起的一次生成（走 `llm_generate`），
   不经过 Agent runner，那些钩子本来不会自动触发。插件在读完终稿后手动调用一次
   `call_event_hook(..., OnLLMResponseEvent, resp)`，于是**拥有这些标签的插件自己去清洗与记账**——
   本插件不需要去猜、也不需要适配别人的标签格式。
   只分发 `on_llm_response`，不触发 `on_agent_done`（本插件的逻辑挂在后者上），所以没有递归问题。
2. **终稿复用本轮的 `extra_user_content_parts`。** 这类插件常把关系档位、时间、用户名等动态状态
   放在这个字段里。终稿走的是独立的一次生成，如果不带上，终稿的语气可能脱离当前关系档位。

### 本插件只碰自己的标签

终稿发出前**只清掉自己的 `[呼叫…]` 标签**，其它任何方括号内容（`[FAV:+5]`、`[叹气]`……）
一律不动：该由哪个插件负责就由哪个插件负责。既然上面那个分发机制已经把"别人的标签"
交还给别人处理，就没有必要（也不应该）再去猜别人的标签格式。

### 需要注意的副作用

终稿会触发一次其它插件的 `on_llm_response`，因此**它也会被当成一次模型输出来记账**。
以好感度为例：如果模型在终稿里又输出了 `[FAV:+N]`，那这一轮就会计两次分。
本插件的规则与结果块模板都只约束自己的呼叫标签，不会去要求别的插件该怎么算；
如果你发现分数涨得偏快，把 `max_rounds` 保持为 1（默认）并观察，或告诉我加个开关。

## 已知限制

- 必须**非流式**。
- 多标签按顺序串行执行，子代理较慢时会累加延迟。
- 终稿会额外消耗一次主模型调用（携带本轮完整上下文）。
- 子代理的「全量工具」装配复用了 AstrBot 内部实现，升级 AstrBot 后建议回归测试。
